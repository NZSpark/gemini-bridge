# ① 设计阶段：侦察 → 契约 → 会话模型 → 风险 → 验收标准

目标：**在写第一行实现代码之前**，把「这个页面的哪些事实可以被依赖、对外承诺什么接口、
会话怎么活、哪里会出人命」全部落成 `doc/design.md`。设计阶段的产出直接决定后面返工量。

## 0. 阶段 0：只读探测（在写第一行业务代码之前）

侦察是**独立的一段**（同族 Claude 把它单列为阶段 0）：只读、不提交任何提示词、不代填代勾。
产出必须是一张**选择器命中表** + 三个关键判定（能不能登录 / 有没有安全挑战 / 输入区在哪）。

判据纪律（两条真事故换来的）：

- **「页面可用」必须含 `navigation_ok`**（`200 <= status < 400`）。HTTP 403 的挑战壳里**仍然可能
  残留可命中的输入框**——只凭 DOM 命中就报成功，是本类项目的第一个真实事故（A5）。
- **命中的元素必须可见**，且挑战判定的三条要**同时**成立：① 文案只在**页面自身**（剔除会话正文、
  输入区、script/style）里找到；② 命中必须可见；③ `challenged = 命中 and 输入区不可用`。
  输入区可用时只记 `challenge_suspect`，**不让正常请求变 503**（A4）。
- 若全部命中为空 → 先归因「环境 / 登录态未就绪」，**不要**据此判定选择器失效。

### 1.1 要回答的六个问题

| # | 问题 | 为什么 |
| --- | --- | --- |
| Q1 | 是否需要登录？登录态怎么持久化？ | 决定用 `launch_persistent_context` + `user_data/` |
| Q2 | 输入框是什么元素？（`textarea` / `[contenteditable]` / 富文本编辑器，**可能有多个**） | 决定写入原语与 `\|\|` 候选选择器；退化页面会多编辑器共存 |
| Q3 | 回复是**同一个节点原地流式更新**，还是每次追加新节点？ | **决定结束判定算法**（内容变化 vs 节点变化） |
| Q4 | 页面上「生成中」有什么可观测信号？（停止按钮 / `aria-label` / 类名） | 主判定依据，比文本稳定更可靠；注意误报（见 §1.4） |
| Q5 | 会话 URL 形态与「新会话」入口？上下文上限的提示文案是什么？ | 会话恢复 / 轮转 / 到顶检测 / `/link` 校验 |
| Q6 | 代码块在 DOM 里的容器？ | 代码提取落盘 |

### 1.2 三条路线（先选路线，再谈实现）

| 路线 | 何时选 | 代价 |
| --- | --- | --- |
| **A 直接复用站点自身的 XHR/JSON 接口**（最稳） | `recon.py --network-log` 看到 JSON POST（带 cookie / csrf 即可复现），且鉴权字段可稳定取得 | 接口可能签名 / 加密 / 频繁改版；需 DevTools 对照一次真实请求 |
| **B 浏览器 DOM 自动化**（默认路线，本 skill 的主体） | 没有可复放接口，或接口签名不可复现 | 慢但通用；本 skill 的排错 / 验收都在这一路 |
| **C 混合：DOM 登录 + 接口回放** | A 可行但登录无法自动化 | 复杂度最高，两套世界观并存 |

recon 的路线结论直接来自「有没有 JSON POST 接口」：没有就**别折腾接口回放**，直接 B。
若走 A/C，脚本故意不采集正文，**必须**自己在 DevTools 里看一次真实结构与流式字段来源。

选 B 之前先确认「无头会不会被挑战页拦截」（ChatGPT 实测 `HEADLESS=1` 停在 `Just a moment...`；
必须**有头**，无显示服务器用 `xvfb-run`）。这是单点否决项：先验一次再排期。

### 1.3 怎么拿答案

```bash
python3 skills/web-to-openai-api/scripts/recon.py \
  --url https://chat.example.com/ \
  --user-data ./user_data \
  --network-log \
  --wait 8 \
  --out ./recon-report.md
```

脚本会：有头启动 Chromium（持久化 profile）→ 打开目标页 → 给你时间手动登录 / 发一条测试消息 →
采集候选选择器、疑似流式容器、网络接口线索 → 输出 Markdown 报告（含可直接粘进 `.env` 的 `||` 串）。
**只读**：不写入、不提交、不回显正文（只报长度/结构）。

手动补充（recon 拿不到的部分）：

- **Q3 流式形态**：发一条会生成较久的消息，用候选选择器数两次节点数：
  数量不变而末节点文本增长 = **原地更新**（最常见）；数量递增 = 追加。
- **Q5 到顶提示**：把会话撑满或在别处拿到截图，**原文抄下提示语**（用于 `CAP_NOTICE_PATTERNS`）。
- **Q5 会话 URL**：从地址栏抄下形如 `/<a|chat|c>/<id>` 的会话地址，写成 `SESSION_URL_RE`；
  同时记下**临时地址形态**（如 `local-chatgpt%3A<uuid>`、`WEB:<id>`）用于绑定校验时拒绝。
- **Q4 误报排查**：确认「生成中」信号不会把侧边栏/标题里的装饰类名命中
  （ChatGPT 曾因 `stopAtEnd-<hash>` 让 `generating` 恒为 True → 收紧为「独立 stop 词」：
  `(^|[-_])stop([-_]|$)`，并优先可见、位于视口下半部的控件）。

### 1.4 recon 报告要落成的表

```markdown
| 用途 | 候选选择器（按置信度排序） | 备注 |
| --- | --- | --- |
| 输入框 INPUT_SELECTORS | form div.ProseMirror[contenteditable="true"] \|\| [contenteditable="true"][role="textbox"]:not([data-language]) \|\| textarea | 页面退化时会有多个，必须逐候选试填校验 |
| 发送按钮 SEND_BUTTON_SELECTORS | button[data-testid="send-button"] \|\| button[aria-label*="Send"] \|\| button[type="submit"] | 提交优先真实键盘 Enter，按钮只兜底 |
| 就绪 READY_SELECTOR | rich-textarea, [contenteditable="true"], textarea | 输入框出现 = 页面可用 |
| 回复节点 RESPONSE_SELECTORS | [data-message-author-role="assistant"] \|\| [data-markdown-text-style] \|\| [class*="MarkdownRoot"] | 取**末节点**；不要把用户消息选进来 |
| 代码块 CODE_BLOCK_SELECTOR | [class*="CodeBlock"], pre | 语言在 [data-language]（旧版在 code 的 class） |
| 生成中信号 | 独立 stop 词控件，可见且视口下半部 | 类名含 stopAtEnd 等**不能**命中 |
| 会话 URL | https://chat.example.com/c/<uuid> | 用于重建回到原会话 + 落点校验 |
| 到顶提示 | "达到对话长度上限" / "start a new chat" | 原文抄录 |
```

> 选择器一律做成**多候选 `||` 串**放进配置，站点改版时只改 `.env`，不改代码；
> 同时准备一个 **DOM 探测脚本**（本项目为 `tests/e2e/test_dom_probe.py`），改版后一键复位。

## 2. 对外契约

### 2.1 必须实现（MVP）

| 端点 | 说明 |
| --- | --- |
| `GET /v1/models` | `{"object":"list","data":[{"id":...,"object":"model","owned_by":...}]}`，供客户端 discovery |
| `POST /v1/chat/completions` | 标准字段 `model / messages / stream / tools / tool_choice`；**未知字段一律 `extra="allow"`，绝不 422** |
| `GET /healthz` | 浏览器是否就绪、初始化错误、会话桶快照 |

### 2.2 可选（按客户端与运维需要）

| 端点 | 何时要 |
| --- | --- |
| `POST /v1/responses` | 客户端是 Codex CLI（`wire_api="responses"`）时；命名 SSE 事件 + `sequence_number` |
| `GET /readiness` | 区分「进程活着」与「真的能干活」；未就绪返回 503 |
| `GET /metrics` / `GET /diagnostics` | 计数、延迟、选择器命中、会话绑定；**不回显正文** |
| `POST /session/reset[?session=<key>]` | 逃生口：下一轮开新会话（**仍会播种历史**） |
| `/link`、`/unlink`、`/bridge ...` | 聊天内命令：由桥**本地应答**，浏览器不可用时仍可用 |

### 2.3 错误契约（提前定死）

统一返回 `{"error":{"message","type","code"}}`，把上游失败**分类**，不要都塞 500。
**每个错误码都要有「谁能观察到它」的判据**——没有可观察依据的错误码就是假承诺：

| HTTP | type / code | 触发 | 可观察判据 |
| --- | --- | --- | --- |
| 400 | `invalid_request_error` | `messages` 缺失 / 空输入 | 校验阶段直接拒绝，不进入浏览器 |
| 400 | `context_length_exceeded` | 网页会话到顶 | 页面文案命中 `CAP_NOTICE_PATTERNS`（**扫描前剔除会话正文**） |
| 502 | `upstream_error` | 页面句柄已死 / 渲染进程崩溃 | `wait_for_selector` **立刻**抛错（≈0 秒，与「熬满超时」区分） |
| 502 | `composer_not_found` | 页面活着但输入区不吃输入 | 候选全枚举后读回仍为空（可恢复：重建后重发一次） |
| 502 | `prompt_submission_failed` | 提交无法确认 | 页面静止且输入区仍留着本轮提示词 |
| 502 | `tool_call_parse_error` | 工具调用解析失败 | 出现标记/围栏却解析出 0 条（诊断 warning） |
| 503 | `unavailable` | 浏览器未就绪（未登录 / profile 被占用） | `/healthz` 报 `degraded` + `init_error` |
| 503 | `challenge_required` | 命中安全挑战且无法继续 | 三条同时成立：页面 chrome 文案 + 命中可见 + **输入区不可用** |
| 503 | `upstream_busy` | 同桶已有请求在跑且等锁超时 | 等锁超过 `BUCKET_LOCK_TIMEOUT_S`（**不触发重试阶梯**） |
| 504 | `timeout` | 等待回复超时（已按阶梯重试） | 超过 `TIMEOUT`，且内容确实不再变化 |
| 429 | `usage_limit_reached` | 上游明确拒绝（额度用尽 / 风控提示） | 页面可见弹窗命中，且本轮确实没生成 |
| 499 | `cancelled`（流内） | 客户端断开 | 检测到 `is_disconnected` → 取消并释放桶锁与页面 |
| 500 | `server_error` | 其它未预期错误 | ——（**不伪装成 503**） |

> 关键原则：**「上游明确拒绝」与「上游无响应」必须可区分**——它们外在常常都表现为超时。
> 另外区分「页面句柄已死」（可自愈重建）与「选择器失效 / 未登录」（不可自愈）：
> 前者专用异常 + 重建，后者如实报错，别互相伪装。
> 完整的错误词汇表（含各码的出处）见 [../SKILL.md](../SKILL.md#错误词汇表提前定死http-由一处集中映射)。

## 3. 会话模型决策链

先回答一个问题：**这条网页会话要活多久、由谁决定轮转？**

**设计原则**：把「是否新开会话」交给**会话自身的健康度与体积**，而不是进程生命周期
（会话会不会过长取决于跑了多少轮，与进程重启过几次无关）。

当前决策链（本项目与同族项目的共同落地形态）：

1. **启动**：默认复用状态文件里的会话；仅当「到顶」或显式配置时开新会话（首轮播种）。
2. **运行**：超过 `SESSION_MAX_TURNS` / `SESSION_MAX_TOKENS` → 下一轮轮转 + 播种。
3. **到顶**：页面出现上限提示 → `context_length_exceeded`(400) + 标记 `pending_rotation`，
   **不要死等到超时**。
4. **重试阶梯**：现有会话 → 恢复**同一个**会话 → **新会话 + 播种**（最后一级）；
   页面重建这一支要**跳过**「换新会话」（否则刚恢复的上下文立刻被扔掉）。
5. **按任务隔离**：`X-<Site>-Session` 头 → 请求体 `user` → 工作目录 → `User-Agent`；
   每桶独立页面 + 独立状态；显式标识永远优先。
6. **逃生口**：`POST /session/reset`（只改状态，下一轮轮转并播种）。
7. **桶页回收**：`MAX_SESSION_BUCKETS` 满时 LRU 关最久未用页；空闲超 `BUCKET_IDLE_TTL_S` 也关。
   **只关页面、状态保留**；正在处理请求的桶绝不回收（用**可重入计数**，不是看锁）。
8. **并发**：默认所有桶共用一把锁（**串行**，分桶只隔离上下文）；要并行必须按桶加锁并接受风控风险。
9. **显式绑定**（可选高级能力）：`/link <URL>` 把桶固定发到指定网页会话；
   绑定时校验 URL 形态（站点白名单 + 会话路径段），发送前对齐并**校验落点**，
   被重定向回首页要告警 + 指标，而不是静默乱发。

**同族分歧（本项目与 GeminiBridge 不同，必须显式选一次）**：

| 议题 | 回到 `state.url`（本项目 / Deepseek） | 新开对话 + 重放历史（Gemini） |
| --- | --- | --- |
| 依据 | 网页会话 URL 稳定，重建后能续上上下文 | 会话 URL 与「当前对话」绑定不稳定，回填易落空白页 |
决定方式：**做一次落点校验实验**——重建后反查真实 URL，若稳定停在该会话就用前者；
若会漂回首页/空白页，就改用「新开对话 + 重放历史」，并先保证播种可用。

**已否决的方案（勿重提）**：

| 方案 | 为什么否决 |
| --- | --- |
| 每次启动就新开会话 | 轴选错了（与重启次数无关）；没有播种能力时会退化成「一条孤立消息」的静默失败 |
| 超时后用上一个会话继续 | 触发条件反了——到顶最可能就表现为超时，复用等于继续用已撑爆的会话 |
| 靠解析层补救被渲染改写的协议 | 缩进/引号已被改写，信息不可恢复 → 换载体 + 真机验证 |

> ⚠️ 前置约束：**「新开会话」与「播种上下文」必须成对出现**。任何轮转/分桶之前，先实现播种。

## 4. 风险、法务与安全

| 风险 | 处理 |
| --- | --- |
| 登录态（Cookie/Session）泄露 | `user_data/` 加 `.gitignore`；只监听 `127.0.0.1`；日志不打印 Cookie |
| 服务被同机其它进程读取 | 调试端点默认关闭（404）且回显不含正文/提示词 |
| 站点风控 | 默认串行；并发开关默认关；控制频率；不共享账号、不做账号池 |
| ToS / 合规 | 仅供个人学习研究；不做验证码绕过、不规避风控 |
| 客户端超时先于服务端 | 服务端超时必须**小于**客户端 HTTP 超时（如客户端 240s / 服务端 180s） |
| 站点改版 | 选择器全部集中配置 + 探测脚本 + 零节点一次性诊断 |
| 无头环境 | 先验证有头可用性；无显示服务器用 `xvfb-run`，不要盲目 `HEADLESS=1` |
| 模型可控的本地工具 | 路径沙箱（根内相对路径）+ 默认 dry-run + 写前备份 |
| 登录态被云盘带走 | `user_data/` **不要**同步到 iCloud / Dropbox（等于把 Cookie 复制出去） |
| 复用已有 Chrome profile | 复制**副本**再启动（Chrome 136+ 拒绝在默认用户目录开远程调试）；副本等于凭据，必须 `.gitignore` |
| 单机其它进程/网页调用本服务 | 可选 `BRIDGE_TOKEN` 式 Bearer 门（默认关闭以保持兼容，只保护生成端点，探活与模型发现保持开放） |
| 配置「写了没用上」（死键） | 漂移测试 + 死键 grep：要么接线，要么删（A7） |
